第一個程式
# 專題課當天要交的東西
研究規劃 = "我這學期要研究什麼"
能力規劃 = "解題與 APCS 要進展到哪裡"
我的分工 = "團隊題目裡，我負責哪一塊"
→ 一份文件，當天交、當場討論

專題課當天，每個人交一份規劃，我會當場一個一個跟你討論。
先想清楚兩件事：這學期我要研究什麼、解題與檢測要走到哪裡。

扉頁
要交
當天

專題課當天，交規劃、當場討論

  • 打字成一份文件，專題課當天帶來交，不收手寫。
  • 交完同一節課就開始一對一討論，所以請先想過，不要到現場才寫。
  • 規劃會被沿用到期中檢核與期末評分，不是寫完就收起來的作文。
當天要討論的人很多，你準備得愈清楚，能問到的東西就愈多。
第一頁
寫什麼
內容

規劃書要寫哪些東西

項目要寫清楚的內容
研究題目你要研究什麼？想解決或想知道什麼？
我的分工如果和別人合作，我負責哪一塊
解題能力現在解到什麼程度、這學期要進展到哪裡
競賽與檢測校內資訊能力競賽、APCS、TOI 練習賽的目標
驗證方式怎麼證明你做到了（成績、題數、作品）
時間安排期中之前做到哪、期末交出什麼
  • 五項都要有，寧可短，不要空。
  • 有困難或還沒想清楚的地方也寫出來，討論的時候可以一起解決。
第二頁
具體
研究規劃

怎麼寫才算「具體」

這樣寫不行為什麼改成這樣
我要做 AI沒有題目、沒有範圍用影像辨識判斷校園垃圾分類是否正確
我要學 Python看不出程度變化從只會基本語法，到能自己寫資料前處理腳本
跟著組員一起做看不出你做了什麼我負責資料蒐集與標註，共約 500 筆
努力完成專題沒有驗證方式期中交出可跑的模型與訓練紀錄
判斷標準很簡單：別人看完，知不知道你「做完了沒有」？寫得出檢核點，才叫具體。
第三頁
能力
能力規劃

解題能力進展怎麼寫

寫成「現在 → 目標 → 驗證」
現在：  只會迴圈與條件，看到題目常不知從何下手
目標：  能獨立解出排序、前綴和、二分搜的基礎題
驗證：  APCS 實作題目標 3 級分
        每週固定完成 3 題，並寫解題筆記
        TOI 三場練習賽全部參加，每場寫檢討
  • 起點要誠實。寫得太高，討論時會被問出來，也對你沒好處。
  • 目標要能在這學期達成，級分、題數、場次都寫成數字。
  • 驗證方式盡量用拿得出來的東西：成績單、題數紀錄、解題筆記。
第四頁
分工
合作研究

有合作的人，分工要寫清楚

  • 共同的題目寫一次就好，重點是你負責的那一塊。
  • 分工要寫得可以被檢查：做什麼、做多少、什麼時候交。
  • 除了團隊的部分，你也可以另外加入自己有興趣的獨立研究。
組內每個人的規劃書都會分開看。「我跟著組員做」不是分工。
第五頁
例一
參考範例

範例一：以競賽解題為主

解題型：用題數與場次當檢核點
研究方向：演算法解題（以圖論與貪心為主）
團隊分工：無，獨立練習
解題能力：現在只會模擬與暴力解
          → 目標能獨立寫出 BFS/DFS 與最短路徑
競賽目標：校內資訊能力競賽進入前段；
          TOI 潛力組三場全部參加，目標穩定解出 2 題
驗證方式：每週 3 題 + 解題筆記；每場練習賽寫一份檢討
時間安排：10 月基礎題型、11 月圖論、12 月綜合模擬
  • 解題型的規劃，把「每週幾題」寫出來最實在。
第六頁
例二
參考範例

範例二：以 APCS 檢測為主

檢測型：級分就是最明確的目標
研究方向：APCS 實作題型整理與練習
團隊分工：無，獨立練習
解題能力：現在 APCS 實作 2 級分，第三題常常寫不完
          → 目標熟練陣列、字串處理與基本資料結構
檢測目標：本次 APCS 實作題 3 級分以上、觀念題 4 級分
驗證方式：整理一份「題型 → 解法」對照筆記；
          考前完成 3 次完整模擬並計時
時間安排：10 月補基礎、11 月題型整理、12 月模擬與檢討
  • 寫上目前級分和目標級分，進步幅度一眼就看得出來。
第七頁
例三
參考範例

範例三：合作研究（有分工）

研究型：分工要寫到數量與時間
研究題目：用影像辨識判斷校園垃圾是否分類正確
團隊分工：三人；我負責 資料蒐集、標註與訓練流程
我的分工：拍攝並標註 500 張照片，建立訓練/測試集
解題能力：同時維持每週 2 題解題練習，不因專題中斷
競賽目標：校內資訊能力競賽仍參加；APCS 維持 3 級分
驗證方式：期中交出可跑的模型 + 訓練紀錄
時間安排：10 月完成資料集、11 月訓練、12 月調參與報告
  • 做研究的人也不要停掉解題練習——三項成績還是會一起看。
第八頁
來源
評分

成績看這三個部分

  • 校內資訊能力競賽、APCS 檢測、TOI 潛力組練習賽（一學期三場）——三項綜合評判。
  • 不是只看某一次考壞或考好，整學期的表現與進步都算。
  • 所以規劃裡要寫清楚：這三項你各自的目標是什麼。
沒有參加、沒有紀錄，就沒有東西可以評——該報名的、該練的，不要漏掉。
第九頁
練習賽
TOI

TOI 練習賽，這學期只有三場

  • 一學期只辦三次，每次為期一週（週一 08:00 到週五 20:00）。
  • 期間內自己挑時間登入開始，作答時間 90 分鐘，開始了就不能中斷。
  • 三場都要參加——錯過一場，這學期就少掉三分之一的紀錄。
日期會在學期初公告在 TOI 官網，公告後我會提醒，但請自己也記在行事曆上。
第十頁
潛力組
TOI

潛力組要練什麼

主題為什麼要先練
排序、貪心最常出現，也是其他題型的基礎
堆疊、佇列資料結構的入門，題目常拿來當工具
樹、DFS、BFS圖論的核心，幾乎每次都會碰到
分治 D&C、基礎 DP難度較高，留到後面再攻
  • 這是潛力組的命題範圍，你的解題規劃可以照這個順序排。
  • 線上賽開放語言是 C / C++，平常練習就要用得順手。
  • 報名時記得填老師代碼：不發個人成績證明，成績是彙整後寄給指導老師。
規劃裡寫「我要練 TOI」太空泛，寫成「第一場前練完排序與貪心」才叫規劃。
第十一頁
評分
評分

這學期的評分，不會像高一那麼寬鬆

  • 分數依實際表現給，不是每個人都從 80 分起跳。
  • 表現不好，會給到 80 分以下，這一點請先知道。
  • 看的是三項成績的表現與進步，以及你自己的規劃有沒有做到。
規劃寫得務實、進度跟得上、東西真的做出來——分數自然不會差。
第十二頁
看什麼
評分

我會看這四件事

面向我會問的問題
三項成績校內競賽、APCS、TOI 練習賽的實際表現
進步幅度比學期初進步了多少？拿得出紀錄嗎？
規劃達成當初說要做的，期中期末做到了嗎？
投入程度有沒有持續練題、主動問問題、按時參加
  • 規劃可以調整，但要主動來談，不能默默放掉。
  • 卡住不是問題，卡住又不講才是問題。
第十三頁
討論
一對一

當場討論，我會問你這三個問題

  • ① 這個題目，你打算怎麼開始？第一週要做的第一件事是什麼？
  • ② 你怎麼知道自己做完了？拿什麼東西證明？
  • ③ 如果做不出來，備案是什麼？題目可以縮小到什麼程度？
  • 這三題答得出來，代表你的規劃是真的想過的。
  • 答不出來也沒關係——我們就是為了這個才要討論。
當天帶著規劃書來，我們一起把它改成做得完的版本。
第十四頁
檢查
當天

來上課之前，自己先檢查一次

  1. 研究題目寫清楚了，別人看得懂我要做什麼。
  2. 有合作的話，我負責的部分寫出來了，而且有數量或時間。
  3. 解題能力寫成「現在 → 目標 → 驗證」三行。
  4. 校內競賽、APCS、TOI 練習賽三項的目標都寫了。
  5. 每個目標都寫得出怎麼證明做到了。
  6. 期中、期末各要交出什麼，寫進時間安排。
  7. 檔案已經打字完成，專題課當天可以直接交。
全部打勾，當天的討論就會很有效率。加油，這學期認真做，是做給自己的。
